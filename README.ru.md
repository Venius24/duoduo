# Дуодуо 🦉

Игровая платформа для изучения **английского** и **китайского** с русского языка.
Свой бэкенд, своя база, два полноценных курса, умные повторения, боссы, лиги
и автотесты. Готова к деплою одной командой.

```bash
npm run setup && npm run dev     # http://localhost:3000
```
Демо-аккаунт: `demo@duoduo.app` / `demo123`

## ✨ Что внутри

### Курсы
| Курс | Язык | Объём |
|---|---|---|
| 🇬🇧 **English Flow** | английский | 6 юнитов · 24 урока · 6 боссов |
| 🇨🇳 **Путь дракона** | китайский | 6 юнитов · 24 урока · драконий босс 🐉 |

Каждый урок собирается из **10 типов упражнений**: выбор перевода, сборка фразы
из плиток, ввод текста (для китайского — пиньинем), аудирование, аудио-диктант,
соединение пар, произношение в микрофон, заполнение пропуска, тренажёр тонов
и грамматические карточки.

### Фичи
- 🧠 **Умные повторения (SRS)** — алгоритм SM-2 сам решает, когда показать слово
- ⏱️ **Боссы юнитов** — бой на время, проходной балл, звёзды за точность
- 🎙️ **Речевая практика** — распознавание речи в браузере (Web Speech API)
- 🎚️ **Тренажёр четырёх тонов** с цветовым кодированием
- 🔥 **Стрики**, 💎 алмазы, ❤️ сердца с автовосстановлением и рефиллом
- 📋 **Квесты дня** с автовыдачей награды
- 🏆 **Еженедельная лига** с ботами-соперниками
- 🎖️ **10 достижений**, уровни с титулами, идеальные уроки
- 🤖 **ИИ-объяснение ошибок** (опционально, по своему API-ключу)
- 🌙 Тёмная тема, звук без ассетов (Web Audio), озвучка слов (TTS)
- 📱 PWA-манифест, адаптив под мобильные

### Технологии
Next.js 15 (App Router) · TypeScript · Tailwind CSS · Prisma (SQLite/PostgreSQL) ·
JWT (jose) + bcryptjs · Zustand · Vitest + Testing Library

Для базовой работы **не нужны внешние сервисы**: база — файл SQLite, озвучка —
синтез речи браузера, звуки — Web Audio.

## 🚀 Быстрый старт

```bash
npm install          # зависимости + prisma generate
npm run gen:secret   # печатает строку JWT_SECRET — вставь её в .env
npm run db:push      # создаст prisma/dev.db
npm run db:seed      # демо-юзер + 26 ботов для лиги
npm run dev
```
Либо одной командой: `npm run setup`.

Перед запуском скопируй `.env.example` в `.env` и подставь свой `JWT_SECRET`.

### Скрипты
| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер |
| `npm run build` | прод-сборка (сама подберёт провайдер БД) |
| `npm start` | запуск собранного |
| `npm test` | автотесты (75 шт.) |
| `npm run typecheck` | проверка типов |
| `npm run verify` | типы + тесты + сборка — то же, что гоняет CI |
| `npm run gen:secret` | сгенерировать `JWT_SECRET` |
| `npm run db:studio` | Prisma Studio |
| `npm run docker:up` | поднять в Docker |

## ⚙️ Переменные окружения

Шаблон — `.env.example`. Обязательны первые две.

| Переменная | Обязательна | Описание |
|---|---|---|
| `DATABASE_URL` | ✅ | `file:./dev.db` (SQLite) или `postgresql://…` |
| `JWT_SECRET` | ✅ | секрет подписи сессий, ≥ 24 символов |
| `DATABASE_PROVIDER` | ❌ | `sqlite` / `postgresql`, если автоопределение не подходит |
| `COOKIE_SECURE` | ❌ | `1` — всегда ставить флаг Secure (нужно за TLS-прокси) |
| `OPENAI_API_KEY` | ❌ | включает ИИ-объяснения; без ключа — локальные подсказки |
| `AI_BASE_URL` | ❌ | любой OpenAI-совместимый API |
| `AI_MODEL` | ❌ | модель (по умолчанию `gpt-4o-mini`) |
| `APP_VERSION` | ❌ | попадает в ответ `/api/health` |

> **В продакшене приложение не стартует** без `JWT_SECRET`, с секретом короче
> 24 символов или с шаблонным значением. Это осознанно: с предсказуемым
> секретом можно подписать токен и войти под любым пользователем.

## 🌍 Деплой

### Выбор базы
Схема Prisma поддерживает оба провайдера, а `npm run build` подставляет нужный
автоматически по `DATABASE_URL`:

| Куда | База | Почему |
|---|---|---|
| свой сервер, VPS, Docker | **SQLite** на постоянном томе | проще некуда, ноль зависимостей |
| Vercel, Netlify, Cloud Run | **PostgreSQL** (Neon, Supabase, Railway) | файловая система эфемерна — файловая БД потеряется между запусками |

### Docker (свой сервер) — рекомендуемый путь

```bash
cp .env.example .env
npm run --silent gen:secret >> .env   # допишет строку JWT_SECRET
npm run docker:up               # docker compose up -d --build
```
Приложение на `:3000`, база — в томе `duoduo-data`.

Контейнер при старте сам применяет схему и при первом запуске сеет ботов.
Он собран multi-stage на standalone-выводе Next.js, работает под
непривилегированным пользователем и имеет `HEALTHCHECK` на `/api/health`.

Если перед ним стоит nginx/Caddy с TLS, добавь в `.env`:
```
COOKIE_SECURE=1
```

### Vercel

1. Заведи PostgreSQL (Neon, Supabase, Railway — подойдёт любой).
2. Импортируй репозиторий в Vercel.
3. В Environment Variables пропиши:
   - `DATABASE_URL` — строка подключения к Postgres
   - `JWT_SECRET` — вывод `npm run gen:secret`
   - `COOKIE_SECURE` = `1`
4. Deploy. Провайдер схемы переключится на `postgresql` сам.
5. Один раз применить схему и засеять лигу:
   ```bash
   DATABASE_URL="postgresql://…" npm run db:push
   DATABASE_URL="postgresql://…" npm run db:seed
   ```

### Проверка после выката
```bash
curl https://<домен>/api/health
# {"status":"ok","db":"up","latencyMs":4,"uptimeSec":12,"version":"1.0.0"}
```
Ответ `503 {"status":"degraded"}` означает, что процесс жив, а база недоступна.

## 🔒 Безопасность

- Пароли — bcrypt; сессия — подписанный JWT в `httpOnly`-cookie на 30 дней.
- Приложение отказывается стартовать с небезопасным `JWT_SECRET`.
- Ограничение частоты: вход — 10 попыток / 10 минут на IP, регистрация —
  5 / час, ИИ-эндпоинт — 30 / 5 минут на пользователя.
  Счётчики по умолчанию живут в памяти процесса; для нескольких инстансов и
  serverless задай `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` —
  тогда счётчик общий (см. `src/server/rate-limit.ts`, ADR 0010).
- Результат урока принимается только по выданной сервером одноразовой попытке:
  проверяются владелец, урок, срок, правдоподобное число заданий и время
  прохождения (ADR 0008).
- «Выйти на всех устройствах» отзывает все выданные сессии (ADR 0009).
- Заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`,
  `Permissions-Policy`; ответы `/api/*` помечены `no-store`.
- Все входные данные проходят через zod-схемы.

## 🧪 Автотесты

```bash
npm test
```

**96 юнит- и интеграционных тестов (Vitest) и 6 сквозных (Playwright):**
- `normalize.test.ts` — нормализация ответов (ё, пунктуация, пиньинь), опечатки
- `core.test.ts` — SRS, уровни/XP, квесты, достижения, тоны
- `content.test.ts` — валидация структуры обоих курсов и направления языков
- `services.test.ts` — интеграция с реальной БД: регистрация/логин, полное
  прохождение урока, проигранный босс, интервалы повторений, лига,
  идемпотентность квестов, регенерация сердец, проверка попыток урока, отзыв сессий
- `security.test.ts` — лимитер частоты (память и Redis с откатом) и проверка секрета
- `speech.test.ts` — распознавание речи всегда завершается
- `components/exercises.test.tsx` — рендер и поведение UI упражнений
- `e2e/lesson-flow.spec.ts` — настоящий браузер: регистрация, полное прохождение
  уроков английского и китайского, подделка результата, «выйти везде»

Сквозные тесты: `npx playwright install chromium` (один раз), затем
`npm run test:e2e`.

Тесты используют отдельные БД `prisma/test.db` и `prisma/e2e.db` и не трогают дев-данные.
CI (GitHub Actions) гоняет типы, тесты, прод-сборку и сборку docker-образа.

## 📁 Структура

```
prisma/            схема, сид (демо + боты)
scripts/           переключатель провайдера БД, генератор секрета
e2e/               Playwright-тесты
docker/            entrypoint контейнера
src/
  content/         курсы: en.ts, zh.ts, генераторы упражнений (builders.ts)
  lib/             SRS, проверка ответов, уровни, квесты, ачивки, TTS/SFX, стор
  server/          prisma, JWT, конфигурация, лимитер, сервисы
  components/      ui-кит, оболочка, раннер уроков, 10 типов упражнений
  app/             страницы + API (включая /api/health)
  instrumentation.ts  проверка конфигурации при старте сервера
src/tests/         автотесты
```

## 🔧 Как добавлять контент

Курсы описываются декларативно в `src/content/en.ts` / `zh.ts`: слова-кортежи,
предложения и функция сборки упражнений (`f.choiceNew`, `f.wordbank`, `f.tone`, …).
Добавить юнит = добавить объект в массив `units`. Валидность структуры
проверяет `content.test.ts`.
